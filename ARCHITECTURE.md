# Architecture

## Overview

off-point is a vanilla JS progressive web app with no build step. All modules use ES module imports. Libraries are vendored from `node_modules` into `lib/` via a postinstall script.

```
index.html          → app shell
style.css           → all styles
sw.js               → service worker (precaching + cache-first fetch)
manifest.json       → PWA manifest
js/                 → application modules (ES modules)
lib/                → vendored libraries (gitignored, generated by yarn install)
icons/              → PWA icons
data/world_z5.pmtiles → bundled low-detail world basemap (zoom 0–5)
```

## Module Graph

```
app.js (entry point)
├── map.js
│   ├── pmtiles-source.js
│   └── openmaptiles-theme.js
├── waypoints.js
│   └── icons.js
├── storage.js
├── sidebar.js
└── export.js
```

## Modules

### `js/app.js`

Entry point. Orchestrates initialization and wires modules together:

- Registers the service worker and GPS tracking
- Initializes the map, sidebar, and waypoint system
- Loads all stored projects from IndexedDB on startup
- Handles view switching (world ↔ region) with `onViewChange`
- Binds the file picker, world view button, and export button
- Auto-restores the last active project

### `js/map.js`

Map layer management built on Leaflet + protomaps-leaflet.

- `initMap()` — creates the Leaflet map instance
- `loadBasemap(map)` — fetches and renders `data/world_z5.pmtiles` as the global basemap
- `addRegion(map, blob, filename, callbacks)` — adds a user-loaded PMTiles region with a bounding rectangle overlay
- `flyToRegion(map, filename)` — switches to region view: shows the detail layer, locks zoom/pan to region bounds
- `showWorldView(map)` — switches to world view: removes detail layers, restores rectangles, unlocks zoom
- `removeRegion(map, filename)` — removes a region and its rectangle from the map

Regions are stored in a `Map<filename, { layer, rect, bounds }>`.

### `js/pmtiles-source.js`

Adapts a browser `Blob` to the PMTiles `Source` interface:

```js
class BlobSource {
  getKey()                    → returns filename (used as cache key)
  getBytes(offset, length)   → slices the blob and returns ArrayBuffer
}
```

This allows PMTiles to read from IndexedDB-stored blobs without network requests.

### `js/openmaptiles-theme.js`

Paint rules and label rules for rendering OpenMapTiles-schema vector tiles. Defines colors and styles for roads, water, landcover, buildings, boundaries, etc.

### `js/waypoints.js`

Waypoint state management and map interaction.

- Listens for map clicks (when enabled) to place new waypoints
- Each waypoint has: `{ lat, lng, stopAfterReach, marker }`
- Markers are draggable; drag updates coordinates and triggers save
- Popup with checkbox toggles `stopAfterReach` → changes marker color
- Maintains a polyline connecting all waypoints in order
- `removeWaypoint(index)` — removes and renumbers all markers
- `getExportData()` — returns clean array without marker references

### `js/icons.js`

Generates numbered SVG marker icons as Leaflet `divIcon`s.

- `blueIcon(number)` — default waypoint marker (blue pin with white number)
- `redIcon(number)` — stop waypoint marker (red pin with white number)

### `js/storage.js`

IndexedDB persistence via `idb-keyval`.

Keys:
| Key | Value |
|-----|-------|
| `projects` | `string[]` — list of loaded filenames |
| `lastProject` | `string` — most recently active filename |
| `map_{filename}` | `Blob` — the PMTiles file |
| `data_{filename}` | `object[]` — waypoint array |

Functions:
- `storeMapFile(file)` — stores blob + adds to project list
- `getAllMaps()` — returns all stored `{ filename, blob }` pairs
- `removeMap(filename)` — deletes map, waypoints, and project entry
- `saveWaypoints(filename, waypoints)` / `getWaypoints(filename)`
- `getLastProject()` / `setLastProject(filename)`

### `js/sidebar.js`

Sidebar UI controller with two panels:

- **World view** (`panel-regions`): lists all loaded regions with bounds and delete buttons
- **Region view** (`panel-detail`): shows region name, bounds, waypoint count, numbered waypoint list with remove buttons

On mobile, the sidebar is a bottom drawer toggled by the handle.

### `js/export.js`

Exports waypoints as a downloadable JSON file:

```js
{ name: "filename-without-extension", waypoints: [{ lat, lng, stopAfterReach? }] }
```

Triggers a browser download via a temporary object URL.

## Service Worker (`sw.js`)

Cache version: `v0`, cache name: `off-point-v0`

**Strategy:** Cache-first, fallback to network. Successful network responses are cached for future offline use.

**Precached assets:** App shell, all JS modules, vendored libraries, Leaflet images, PWA icons, and `data/world_z5.pmtiles` (~15MB).

**Lifecycle:**
- `install` — precaches all URLs, calls `skipWaiting()`
- `activate` — deletes old caches, calls `clients.claim()`
- `fetch` — returns cached response if available, otherwise fetches and caches

User-sideloaded maps are NOT cached in the service worker — they're stored in IndexedDB via `storage.js`.

## Data Flow

```
User loads .pmtiles file
  → storeMapFile() saves blob to IndexedDB
  → addRegion() creates PMTiles instance from BlobSource
  → protomaps-leaflet renders vector tiles on the Leaflet map

User clicks map
  → waypoints.js adds marker + updates polyline
  → onChange callback saves to IndexedDB via storage.js
  → sidebar updates waypoint list

User clicks Export
  → getExportData() strips internal state
  → exportRoute() triggers JSON download

App reload
  → getAllMaps() loads blobs from IndexedDB
  → addRegion() for each stored map
  → getLastProject() determines which region to restore
  → flyToRegion() enters that region view
```

## Deployment

GitHub Actions workflow (`.github/workflows/deploy.yml`):

1. Checkout + `yarn install`
2. Copy vendored libs from `node_modules` to `_site/lib/`
3. Copy app files to `_site/`
4. Upload `_site` as GitHub Pages artifact
5. Deploy via `actions/deploy-pages`

GitHub Pages source must be set to **"GitHub Actions"** (not "Deploy from a branch").
